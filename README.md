# JiYu Studio

极域电子教室 V6.0 的第三方教师端实现。使用 Python 处理网络协议，使用 PyQt6 提供原生桌面界面，无需 Electron、浏览器或独立前端服务。

本项目基于已有的 CLI 协议研究成果改编，当前阶段重点是桌面交互，不代表已经覆盖官方教师端全部功能。后续协议分析仍在继续。

## 界面与功能

- 课堂总览：在线学生、计算机名称、实时缩略图、搜索与全班预览。
- 学生信号：解析学生端 ANNO 状态块，显示举手状态与人数，并保留状态标志供诊断。
- 文件提交审批：识别 QRMS 请求，显示事务 GUID、目录、文件列表和总大小，可发送 RRMS 接受或拒绝。配置文件接收端口且接受请求时，教师端会惰性启动一个本地 MiniMedia 接收服务；端口为 0 时仍只完成 RRMS 审批。
- 文件接收事件：接收服务的 started / progress / completed / error 事件经 `gui_events.submission_events` 桥接到 GUI 线程；日志、消息中心和设备详情显示学生 IP、文件名、字节数、接收路径和错误。
- 消息中心：接收学生聊天并显示双向记录，发送状态写入日志。
- 学生管理：设备信息、进程列表、窗口列表。
- 远程操作：连续观看、远程控制、黑屏与解锁、消息、远程运行、打开网页。
- 屏幕广播：支持 feature 1 启停协议与状态管理；媒体推流尚未完成，启动按钮不代表学生端已显示画面。
- 学生演示：提供 feature 4 的实验性语音启停控制，须指定监听端口；解析 ANNO `0x04` 状态位。屏幕分发、观看者列表和媒体监看尚未闭合。
- 进程与窗口管理：按已上报的 PID 或窗口句柄发送结束命令。
- 电源操作：关机、重启，支持倒计时提示；执行前二次确认。
- 日志：在界面中查看协议事件和错误，可切换 DEBUG 文件日志。
- 班级管理：新建并选择当前班级、从在线学生导入、分组增删改、成员与组长管理。
- 自动签到：当前班级学生上报系统信息时更新计算机名和登录用户，并在本次在线记录中从未在线变为在线时签到；重复 MESS 不重复计数。表格显示签到/签退次数与时间，可导出带 UTF-8 BOM 的 CSV。

CLI 入口保留，便于协议调试。

## 环境

- Windows 10/11。
- Python 3.10 或更高版本。
- 学生端与本机位于同一局域网，UDP 组播或广播可达。
- 已允许 Python 通过 Windows 防火墙。

连续 H.264 观看依赖 `imageio-ffmpeg` 提供的 FFmpeg。远程控制沿用原实现的独立显示窗口，键盘兼容性仍是实验状态。

## 安装与启动

建议在虚拟环境中安装依赖：

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python teacher_gui.py
```

也可以直接在已有 Python 环境中运行：

```bash
python -m pip install -r requirements.txt
python teacher_gui.py
```

启动 GUI 时会绑定协议端口并发送教师端发现宣告。仅进行界面开发时，可设置 `QT_QPA_PLATFORM=offscreen` 做离屏验证，不要把离屏测试当成协议实机验证。

## 一键构建独立 EXE

```bash
python build.py
```

脚本自动安装构建依赖，默认生成目录版：

```text
build/JiYuControl/JiYuControl.exe
build/JiYuControl.zip
```

目录已包含 Python 运行时、Qt、Pillow、Tk、中文字体和 FFmpeg。将 ZIP 解压到目标 Windows x64 机器后，运行目录内的 EXE 即可，不需要安装 Python、pip 或独立解码器。请保留整个程序目录，不要只复制 EXE。

目录版不需要在每次启动时解压，启动性能优于单文件。已安装全部依赖时可用 `python build.py --skip-deps` 加速后续构建；`python build.py --onefile` 仍提供兼容的单文件构建。

构建目录与中间文件不进入 Git。

原 CLI：

```bash
python teacher_sim.py
```

CLI 输入 `help` 查看完整命令。

## 网络配置

教师端侧栏的齿轮按钮打开“频道与接收设置”，可设置 **1–32 频道** 和 **文件接收端口（0–65535）**，保存到程序目录的 `classroom_config.json`。两个值在下一次启动时生效；当前运行中的频道、接收端口和已启动的接收服务不会重载。界面显示当前实际运行值。配置文件中的 JSON 损坏或某一字段无效时，频道与端口各自回退到默认值，不会互相影响。

显式设置的 `TEACHER_CHANNEL` 环境变量优先于配置文件的频道；显式设置的 `TEACHER_SUBMISSION_PORT` 环境变量优先于配置文件的 `submission_port`。后者必须是整数：`0` 禁用文件接收，`1–65535` 为有效监听端口；非法值会在启动时报错。`JIYU_CONFIG_PATH` 可改变配置文件位置。`classrooms.json` 及班级数据仍在同目录。

**没有默认官方端口。** 现有静态证据没有确认原版学生端 MiniMedia 上传使用的监听端口，因此本项目默认 `submission_port=0`；必须显式选择一个本地高端口（例如 41234）才会启动接收服务。该端口只供本项目独立模拟工具联调，不代表官方协议默认值。

班级页的可编辑下拉框用于输入新班级名称；点击“新建班级”会同时将其设为当前班级。只有点击“导入在线学生”才把当前在线终端加入班级，网络上报不会自动添加未知 IP。自动签到在独立写盘线程中更新 JSON，UDP 接收线程只投递轻量事件。

当前协议没有可靠的下线超时语义，因此不按心跳间隔猜测离线。正常退出教师端时，仅为本次运行已自动签到且仍在线的学生写入签退；异常终止无法保证这一步完成。历史签到次数会保留，新的运行可再次签到。

默认监听：

| 通道 | 地址 | 用途 |
| --- | --- | --- |
| 主通道 | `224.50.50.42:4705/UDP` | 发现、控制、缩略图 |
| 会话通道 | 按频道计算，频道 1 为 `225.2.2.1:5512/UDP` | 登录、消息、信息上报 |
| 连续观看 | 学生端 `4806/TCP` | UMSP channel 10 桌面流 |
| 文件接收 | 默认不监听；配置后在 `教师机 IP:<自定义端口>/TCP` | 本项目 WORB/LIFD/TRFD/BFPU 本地接收实验 |

自动选错网卡时，可在启动前指定：

```powershell
$env:TEACHER_IP = "192.168.1.10"
$env:TEACHER_CHANNEL = "1"
$env:TEACHER_SUBMISSION_PORT = "41234"
python teacher_gui.py
```

常用可选环境变量：

| 变量 | 作用 |
| --- | --- |
| `TEACHER_IP` | 指定本机 IPv4 地址 |
| `TEACHER_PEER_IP` | 指定学生机提示地址，辅助选择直连网卡 |
| `TEACHER_NETWORK` | 限定本机网段，例如 `192.168.1.0/24` |
| `TEACHER_CHANNEL` | 频道，范围 1–32，优先于配置文件 |
| `TEACHER_SUBMISSION_PORT` | 文件接收端口，0 禁用、1–65535 有效，优先于配置文件 |
| `JIYU_CONFIG_PATH` | 指定 `classroom_config.json` 的完整路径 |
| `TEACHER_NAME` | 教师显示名称 |
| `TEACHER_TCP_PORT` | 连续观看端口，默认 4806 |
| `TEACHER_CONTROL_MODE` | 远控模式，默认 2；0 为 Share |
| `TEACHER_SAVE_PREVIEWS` | 设为 1 时将最新修复预览保存到桌面 |
| `TEACHER_DEMO_VOICE_PORT` | 实验性 feature 4 语音监听端口；GUI 中也可输入，不代表已建立媒体连接 |

运行日志写入程序所在目录的 `teacher_sim.log`，包含网络协议事件、`[UI]` 操作记录及文件接收事件（学生 IP、文件、字节、路径、错误）。日志采用 UTF-8，单份最大 10 MiB，自动保留三份轮转备份，启动时不会清空历史记录。连续观看输出位于同级 `teacher_remote_view` 目录。

## 文件提交的本地接收实验

QRMS 请求仍然只通过 UDP 到达教师端；RRMS 接受/拒绝是 52 字节 UDP 审批包，本身不携带文件内容。接受且配置了端口时，教师端在发送 RRMS **之前**启动唯一的全局 `MiniMediaServer`：`start()` 返回实际监听端口，`shutdown()` 时调用 `close()`。若服务启动或 RRMS 发送失败，请求保持 `pending` 并报错，不伪装成已批准。

接收文件根目录为程序目录下的 `submissions/`（已由 `.gitignore` 忽略）。全局服务使用统一的 `submissions/` 根目录，但每个已批准事务有独立的 `submissions/<学生IP>/<时间戳>-<事务GUID>-<序号>/` 归档目录。接收服务拒绝重名纯文件名；教师端还拒绝并发同名上传并给每个完成文件分配唯一路径，避免覆盖。重复审批、端口为 0 或拒绝审批都不会产生真实文件。

`completed` 事件表示**本地接收服务已经把文件写入本机**，并在 GUI 消息中心、日志和设备详情显示接收路径及字节数。它不是官方协议完成应答：现有静态证据没有证实原版服务端在上传完成后是否发送完成应答，也没有证实其 magic 和字段。独立上传工具发出结束帧后不等待、不解析完成回包；这里的 `completed` 不得解读为原版学生端确认或实机兼容。

请只使用本项目的独立工具做离线或自建局域网联调：

```bash
python tools/minimedia_client.py --host <教师机IP> --port <自定义端口> <本地文件>
python tools/student_sim.py --teacher-ip <教师机IP> --channel 1 \
  --submission-port <同一个自定义端口> --upload-on-approve
python tools/student_sim.py --self-test
```

`tools/student_sim.py` 默认只发送 QRMS 并处理 RRMS，不建立 MiniMedia 连接、不发送文件内容。只有同时显式指定非零 `--submission-port` 和 `--upload-on-approve`，且 RRMS 严格批准、匹配此前选择的文件后，才会按需调用独立上传客户端。`tools/minimedia_client.py` 也可由命令行单独运行，仅读取用户显式给出的一个文件。不要把该工具接到原版教师机传敏感文件，也不要把本地高端口测试说成与原版学生端实机兼容。详细限制见 [tools/README.md](tools/README.md)。

## 使用注意

1. 先确认学生出现在课堂总览，再请求信息或预览。
2. 连续观看前建议用 CLI 的 `view_probe <IP>` 检查 TCP 端口。
3. 远控依赖已建立的观看通道；键盘输入尚未在所有 Windows 会话上验证。
4. 黑屏设为 0 秒时需手动解除；退出程序不会代替你验证学生端已恢复。
5. 结束进程、关机与重启没有可靠的结果回执，应刷新信息或通过其他方式核实。
6. 文件接收端口保存后须重启教师端；显式环境变量会覆盖配置文件。端口 0 时，RRMS 接受仅表示审批。

## 安全模拟学生端

`tools/student_sim.py` 是独立维护的联调工具，不导入教师端或绑定教师端口，支持 GUI 与 CLI：

```bash
python tools/student_sim.py --self-test
python tools/student_sim.py --teacher-ip 192.168.1.10 --channel 1
```

- 使用两台机器、宿主机与 VM，或为师生两端配置不同有效 IP。**同机同 IP 无法联调**，因为教师端会忽略来自自身 IP 的包。
- 师生必须使用相同频道；模拟端默认按教师端相同公式计算会话组播地址与端口。
- 支持模拟登录、信息上报、聊天、举手、QRMS/RRMS 文件提交状态及教师命令时间线。
- 默认所有控制仅记录提示；黑屏、锁屏、远控、关机、重启和结束进程即使启用受限执行也不会真正执行。
- 详细参数、当前支持矩阵和日志说明见 [tools/README.md](tools/README.md)。模拟器尚不提供真实屏幕视频；默认不上传文件内容，只有显式开启上传开关和端口且教师批准后才会发送此前选中的文件。
