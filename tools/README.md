# 极域 V6 模拟学生端

`student_sim.py` 是用于教师端联调的独立 UDP 模拟器，不导入 `teacher_sim`，不会绑定教师端 socket 或启动教师后台逻辑。默认显示 GUI，也可用 `--cli`；事件时间线和 `tools/student_sim.log` 同时记录网络事件与 UI 操作。

## 重要限制：不能同机同 IP 联调

- 学生固定监听 UDP 4705 和频道会话端口；与教师同机还会争用这些端口。
- 更关键的是，当前教师端固定忽略来源 IP 等于自身 IP 的包。因此 **同机、同 IP，即使换端口也不能形成登录闭环**。
- 推荐两台机器、宿主机与 VM、两个网络命名空间，或给师生两端配置不同的有效局域网 IP。双方防火墙需放行 UDP。
- `--bind-ip` 必须是本机实际存在的学生侧地址；`--teacher-ip` 是教师侧地址。工具会主动拒绝两者相同。`127.0.0.1` 和 `0.0.0.0` 不适用于同机师生联调。

## 启动

在项目根目录执行：

```bash
# 无网络自检，不需要 PyQt6，也不绑定端口
python tools/student_sim.py --self-test

# GUI；不写 --bind-ip 时根据到教师的路由自动选网卡
python tools/student_sim.py --teacher-ip 192.168.1.10 --channel 1 \
  --computer-name STUDENT-01 --user-name student01

# CLI
python tools/student_sim.py --teacher-ip 192.168.1.10 --bind-ip 192.168.1.20 \
  --channel 1 --cli
```

也可用 `python -m tools.student_sim ...`。频道支持 1–32；默认会话地址按教师公式计算，频道 1 为 `225.2.2.1:5512`。`--session-port` 仅供特殊网络实验，正常联调不要覆盖。`--main-port` 同时设置教师目标端口和学生监听端口，默认 4705。

文件上传默认关闭：`--submission-port` 为 0（默认）时，即使教师批准也只完成 RRMS 审批，不建立 MiniMedia 连接。只有同时给出非零 `--submission-port` 与 `--upload-on-approve`，才会在严格批准后按需上传 `submit` 所选文件；端口必须显式配置，不存在默认值。

CLI 输入 `help` 查看命令，主要包括 `chat 文本`、`handup`、`handdown`、`submit 文件...`、`info`、`status`、`login`、`quit`。GUI 提供对应按钮、状态区和可见事件时间线。

## 观察模式与受限执行

默认是观察模式：所有教师命令只更新模拟状态并显示提示，不启动外部程序。

`--execute` **不是真实学生模式**。它只允许：

- 用系统浏览器请求打开格式有效的 `http://` 或 `https://` 地址；
- Windows 上无参数启动 System32 中实际存在的 `notepad.exe` 或 `calc.exe`，绝对路径也必须准确指向白名单目标。

无论是否指定 `--execute`，黑屏、锁屏/锁键鼠、远程控制、关机、重启、结束窗口或进程都 **只提示，绝不执行**。工具没有这些危险动作的实现分支。教师端实验性的远程频道/自动登录设置也只观察请求值，不重绑端口、不改注册表、不修改实际频道（见下文）。

### RRMS 提交流程

- QRMS 与 RRMS 共用事务 GUID；学生状态区显示 `pending`、`approved` 或 `rejected`、待处理 GUID、文件数和总大小，GUI 时间线与 CLI 同时显示处理结果。
- RRMS 固定 52 字节：28 字节公共头（`RRMS`、版本 `0x10000`、声明长度 `0x18`、GUID）和 `<6I>` 负载（学生 ID、`accept`、`arg2`、64 位配额、最大文件数）。长度、魔数、版本或声明长度不符时忽略；来源不是教师、GUID/学生 ID 不匹配时也忽略并记录。
- 仅 `accept != 0 && arg2 != 0 && arg3 != 0` 为批准。拒绝会显示教师拒绝；`arg2=0` 单独显示配额/文件数限制。重复回复只记录，新 QRMS 会替换 pending 请求。
- 默认批准只把状态改为 `approved` 并提示不会发送文件内容。只有显式开启上传开关（非零 `--submission-port` 且 `--upload-on-approve`）时，才会在严格批准后按需调用独立工具 `tools/minimedia_client.py`，逐个上传用户显式选择的文件；该工具没有默认端口，见下文。

### 远程频道/自动登录（仅观察）

教师端实验性控制面会单播一个 COMD 包：外层是 `build_comd_command_ex` 的 DMOC/COMD 包装（`cmd_code=0x80000010`），内层 payload 共 32 字节，为 `<IIII>`（`category=0x4000`、`flags=0`、`subcase=7`、`length=12`）+ `<III>`（未知字段 0、`AutoLogin`、`ChannelId`）+ 末尾 4 字节 NUL。

`tools/student_protocol.py` 提供独立构造器 `build_remote_channel_settings()` 与严格解析器 `parse_remote_channel_comd()` / `parse_remote_channel_settings()`，仅供自检使用，不导入也不依赖教师端代码。学生端严格校验包总长、声明长度、负载长度 32、各字段位置、频道 `1..32` 与 `AutoLogin` `0/1`；非法包、非法字段和其它 `category=0x4000` subcase 都只产生可见提示事件，不写入状态、不执行动作。

合法包**只**把 `requested_channel` / `requested_auto_login` 写入 `StudentState`，状态行显示"请求的频道/自动登录"，时间线产生"远程频道设置（仅提示）"事件。绝不重新绑定端口、修改注册表、修改实际频道或执行任何系统动作；`--channel`、`--main-port`、`--session-port`、组播组、会话端口、观察模式与危险动作白名单约束全部保持不变。CLI 的 `status` 与 GUI 状态区、事件时间线会自动显示，无需新增命令；`--execute` 也不改变此行为。

**完整远程设置大结构未知**：静态证据只证实内层 payload 的 `+0x00 category`、`+0x04 flags`、`+0x08 subcase`、`+0x0c length`、`+0x10 settings` 五个字段位置，以及 `subcase=7` 中 settings `+0x04 AutoLogin`、`+0x08 ChannelId` 两个 DWORD。`length` 的精确语义、settings `+0x00` 的含义、其余七路 subcase 的完整布局/默认值/枚举，以及注册表写入、频道切换、重启/重连效果与官方师生端兼容性均未证实；工具不伪造常量，也不实现这些设置。

### 行为限制（COMD `0x200`/`0x17`，仅观察）

教师端行为限制命令同样是 `cmd_code=0x80000010` 的 DMOC/COMD 包装，内层 payload 共 32 字节，为 `<IIII>`（`category=0x200`、`flags=0`、`command=0x17`）+ `<II>`（`App`、`Web`）+ `<III>`（`U盘`、`光驱`、`打印`），即 `+0x0c` 起连续五个 DWORD。

| 字段 | 取值语义 |
| --- | --- |
| `U盘`、`光驱` | 0 开放、1 只读、2 禁止执行、3 完全禁止 |
| `打印` | 0 不限制、2 全部禁止 |
| `App`、`Web` | 学生端不解释；0 为默认，1/2/3 语义**未验证** |

学生端只要求 payload 至少 `0x20` 字节，解析后写入 `StudentState.restrictions`（`BehaviorRestrictions`），状态行显示"行为限制：…"并以 `App 未验证（n）` / `Web 未验证（n）` 标注，时间线记一条"行为限制"摘要。payload 不足 `0x20` 字节时只产生"仅提示"事件记录长度不足，不解析、不改状态、不抛异常；未识别的枚举值原样显示为"未知值（n）"。

**只记录、绝不执行**：不挂载/只读化 U 盘与光驱、不禁用打印机、不拦截程序启动或网址访问，也不修改策略或注册表；状态行因此固定带"（仅记录，不执行）"。`--execute` 不改变此行为。

## 与 `teacher_gui.py` 联调

1. 在教师机运行主项目教师端，学生机使用相同 `--channel`，并将 `--teacher-ip` 指向教师机真实局域网 IP。
2. 启动模拟学生后，教师课堂总览应出现学生 IP；随后可请求信息、发送聊天、切换黑屏或发送远程命令。
3. 学生时间线应依次显示登录回执、LPNT/DMOC 和对应操作；教师端应收到系统信息/列表、聊天、ANNO 或 QRMS 日志。
4. 默认 GUI 的“提交文件请求”只让教师看到 QRMS 请求，不会继续上传文件内容；显式开启上传开关后才会在严格批准后上传用户选择的文件。观看/远控同样不会开放学生媒体或输入服务。
5. 若登录无回执，先检查师生 IP 是否不同、频道是否一致、路由/组播与防火墙，再查看两端日志。不要把同机同 IP 当作端口问题反复重试。

日志为 UTF-8，单份最大 2 MiB，保留两份轮转备份。

## 独立实验上传工具 `tools/minimedia_client.py`

`tools/minimedia_client.py` 是**独立的实验性 MiniMedia 上传工具**：它不是 `student_sim.py` 的启动依赖，**默认配置下 `student_sim.py` 仍不会自动上传文件内容**，观察模式与受限执行策略不变。默认时 GUI“提交文件请求”与 CLI `submit` 只发 QRMS 请求、处理 RRMS 状态，不打开 MiniMedia 连接，不读取或发送所选文件的内容；只有显式开启上传开关（非零 `--submission-port` 且 `--upload-on-approve`）后，`student_core.py` 才会按需惰性加载本工具，上传用户显式选择的文件。命令行直接运行本工具时，只读取用户显式给出的那一个本地文件。

- **端口必须显式配置**：工具没有默认端口，`--host` 和 `--port` 都是必填参数。现有静态结论未证实原版学生端实际监听端口，工具不会猜测端口，也不会自动发现服务。
- **只读取用户显式选择的本地文件**：命令行直接运行时，唯一路径参数是用户显式给出的文件位置；上传前打印目标主机、端口、文件路径与字节大小。工具不扫描目录、不读取其它文件，也不在默认配置下被任何模拟学生流程自动调用。
- 连接流程（依据 `temp/minimedia-server-findings.md`）：TCP 连接后先发 `WORB`（不等待应答），再发 `LIFD` 文件信息；等待并按 12 字节头严格解析 `TRFD`，处理 TCP 拆包/粘包并限制最大帧长，`status != 0` 立即报错；随后按 16 KiB 读取文件并发送 `BFPU` 数据块，**不等待任何逐块应答**；最后发送零长度、`status=0` 的 `BFPU` 作为完成，随即关闭连接。

```bash
python tools/minimedia_client.py --host 192.168.1.10 --port 12345 C:\path\to\file.txt
```

- **联调状态：尚未与原版学生端联调，完成应答未证实。** 已用本地 mock server（`temp/verify_minimedia_client.py`）、独立接收服务的真实 TCP 测试（`temp/verify_minimedia_server.py`）和端到端测试（`temp/verify_minimedia_e2e.py`）验证 `WORB`、`LIFD`、带状态的 `TRFD`、分块 `BFPU`、零长度结束帧、中文文件字节一致及异常清理；这只证明本项目教师端与模拟工具互操作。原版服务端在上传完成后是否发送完成应答、其 magic 与字段都未经静态结论证实，因此工具在发出结束帧后不等待、不解析任何回包，也不宣称已与原版兼容；`TRFD` 成功仅表示文件信息请求被接受。请勿用它向真实教师机传送敏感文件。

其余限制（不同 IP、观察模式、绝不执行危险命令）不变；本工具不启动教师端逻辑，也不修改主项目代码。
